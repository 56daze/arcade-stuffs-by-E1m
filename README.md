## 1. 基础物件语句格式

### tap

```text
(时间, 轨道);
```

| 例 | 说明 |
| --- | --- |
| `(1000,1);` | 1000ms 处左 1 轨地键 |

### hold

```text
hold(起始时间, 结束时间, 轨道);
```

| 例 | 说明 |
| --- | --- |
| `hold(1000,2000,4);` | 1000–2000ms 间右一轨长条 |

### arc

```text
arc(起始时间, 结束时间, 起始x坐标, 结束x坐标, 缓动类型, 起始y坐标, 结束y坐标, 颜色, sfx路径, 类型);
```

**参数详解：**

**缓动类型：**

| 值 | 含义 | 类似形态 |
| --- | --- | --- |
| `s` | 直线（Linear） | `/` |
| `b` | 贝塞尔（Bezier） | `∫` |
| `si` | 正弦渐出（OutSine） | `J` |
| `so` | 正弦渐入（InSine） | `ſ` |

- `sisi` / `siso` / `sosi` / `soso`：前一半为 x 轴缓动，后一半为 y 轴缓动。
- b 型蛇则是 x 轴和 y 轴都是 Bezier。

**颜色：**

| 值 | 颜色 |
| --- | --- |
| `0` | 蓝 |
| `1` | 红 |
| `2` | 绿 |
| `3` | 灰 |

**sfx 路径：**

- 没有时填 `none`；有时填 `[文件名]_wav`，例如 `glass_wav`，此时 "glass.wav" 应与 `base.ogg` / `base.jpg` / `.aff` 同级。
- 填写路径会导致它的天键变成 sfx Arctap 外观（类似 4.0 许多曲目中的那样），并在击打成功时播放 sfx。

**类型：**

| 值 | 含义 |
| --- | --- |
| `false` | 蛇（音弧 / arc） |
| `true` | 黑线（音轨 / trace） |
| `designant` | 红色黑线（类似 Lament Rain 与 Designant. 异象中的那种），并同步染色它的天键 |

示例：

```text
arc(1000,2000,1.00,0.00,sisi,1.00,0.00,1,none,false);   // 右起下拉红蛇
```

### arctap

```text
arc(...)[arctap(时间), arctap(时间)......];
```

> **注意**：天键必须基于黑线创建。一些平台支持实体蛇上加天键，一些则不支持。保守起见建议统一使用黑线上天键。

| 例 | 说明 |
| --- | --- |
| `arc(1000,2000,1.00,0.00,si,1.00,0.00,1,none,true)[arctap(1000),arctap(1500),arctap(2000)];` | 前例蛇的黑线版本上有三天键 |
| `arc(1000,1001,0.50,1.00,s,0.50,1.00,1,none,true)[arctap(1000)];` | "SingleArctap" 的实际实现方式 |

### 特殊天键

形如 HIVEMIND INTERLINK 中大小键的天键。

在 v5.5.6 或更高版本的本体 / 壳子 / 兼容的制谱器中，颜色为 3 的 0ms 蛇会被读作类似于被横向拉伸的天键，判定范围随之改变拉伸，判定方式类似天键。很可惜 a1 只截至 4.0.0，23 年停更。

示例：

```text
arc(1000,1000,1.00,0.00,si,0.50,0.50,3,none,true);   // 宽两轨的半高大小键
```

## 1.1 各形式 arc 写作细节

> arc（蛇）是 Arcaea 的**精髓**。各类形形色色的蛇都离不开以上几种基础类型。
>
> （对，长蛇是单蛇拼出来的，不要像我小时候（单星前）一样以为是在长蛇上加判定点（））

个人认为写蛇在外观上追求 **不平滑 → 平滑 → 不平滑** 的个人水平发展过程，力求能够实现平滑，而后追求更具多样性的非完全平滑蛇。手感上更需仔细考量，难以量化。

### 螺旋 / 弧线蛇平滑思路示例

写出由 `siso` 与 `sosi` 交替形成的螺旋蛇后，若不是严格等距等直径螺旋，很可能产生斜率不匹配的情况。此时调整 **斜率剧变处** 的判定点坐标实现平滑。

若单条 `si` / `so` 蛇被分割，希望增大整条蛇凸度而不增减凸点：对两部分一贯使用 `si` 或一贯使用 `so`，并微调判定点坐标，将 **斜率突变** 逼近到可接受的范围。

（如果你不理解为什么螺旋蛇要用 `siso` 和 `sosi` 交替，可以去了解螺旋运动分解、圆周运动分解与弦函数，或者直接实践试试看）

经验而谈，用的多就熟了。

### 常见蛇型实现思路示例

**amydata 式高架桥**

最简单的特殊蛇。一般由一条蛇以恒定间隔切分而成。视觉上为高密度、多判定点的一整条蛇。（也被称作千足虫？）

**stasis 式碎蛇**

一般由短 `s` 蛇以恒定长度 / 间距，跟随某个运动轨迹排列（一般这里需要一条基准蛇），视觉上像是整条蛇被**有规律等间距地**挖去了一些部分，造成间隔模式。（ `– – – –` ）

> 注意：约定俗成下，碎蛇之间需要黑线连接。但在 BYD 和 ETR 难度下不严格限制。

**直角碎蛇**

在前者基础上去除每条碎蛇的坐标移动。看起来像 "一颗一颗的不动直蛇按某位置规律落下来"。（ `_ – _ – _ –` ）

**弓蛇**

旧版本霸主。实现方式：

- **硬弓蛇**：由不动的 `s` 蛇和动的 `s` 蛇组成，动的一般时长较短，通常是 4 分或 8 分。起始时间在节拍处（特殊处理也可让结束时间在节拍处）。（ `__/￣\__/￣` ）
- **软弓蛇**：让不动 `s` 蛇动起来，削弱转折处的角度。可使用缓动，一般选择 `si`。~~（没有合适的符号来写生，自己实操吧）~~

**直角蛇**

实现方式为不动直蛇 + 0ms 移动直蛇。（ `__|￣|__|￣` ）

> 注意：约定俗成下，0ms 蛇通常不作为结尾（因其没有判定，这么做通常没有现实意义，特殊设计除外）。若要以拉直角结尾请附带小短蛇。
> ~~（你也不想让你心爱的直角蛇失去工作吧？）~~

**折线蛇**

由左右波动的 `s` 蛇构成。通常写法是基于两条完整蛇作为包络批量生成。（ `/\/\/\/\` ）

**折线蛇特殊用法**

- **闪电蛇**（或蛇中间的 "闪电"）：实现方式为在蛇局部加上一次波动。让它 "左右左" 或 "右左右" 移动，看起来像闪电或心电图波动。这是踩某些情形下节拍的好方法。通常全使用 `s` 蛇。（ `—^v—` ）
- **衰减折线蛇**：观感类似 808 kick 的波形图。实现方式：激增波动而后波动范围衰减，通常衰减曲线为 `s` 或 `so`。作为黑线使用放置在 tap / arctap 后可提升打击感。
- **锯齿蛇（saw 型）**：由移动的 `s` 蛇与 1ms 直蛇构成。就像把折线蛇中 **朝一个方向的那些部分** 全部压扁。一般来说也是基于两条原蛇作为包络生成。观感类似锯齿波。（ `/|/|/|/|` ）

> **注意：请避免零或负时长 hold，零时长 arc / trace 可容忍。**

## 2. 时间组相关应用

TimingGroup 是实现变速、变 BPM、差速等基本变化 / 演出的基础。首先应明确知识。

**基础 BPM**：一般设为歌曲最基础的 BPM（或倍率），谱面流速为 `设定流速 * (timing语句中的bpm / 基准bpm)`，两 BPM 相等时设定流速 = 实际流速。

**设置 timing**：一般设为歌曲 BPM，与基准 BPM 需保持一致。

### timing 语句

```text
timing(时间, bpm, 每小节节拍数);
```

一般地，每个时间组**必须填写**最基本一条 timing：

```text
timing(0,歌曲bpm,4.00);
```

这是让谱面能被正常读取，且 BPM 正确（节拍线正确）的关键。

### SV 实现思路

**变 BPM**：首先需明确 BPM 如何变化，然后写出对应语句即可。

例：歌曲起始 BPM 是 180，在 1000ms 处变为 190，1200ms 处变为 200。我们需要根据歌曲 BPM 变化而改变节拍线密度。

```text
timing(0,180.00,4.00);
timing(1000,190.00,4.00);
timing(1200,200.00,4.00);
```

一般情况下明确变化规律时，优先思考经过几拍（时值）变成什么 BPM，而不是以绝对时间确定变化点。（当然写语句的时候还是要考虑绝对时间，这里是介绍更高效的确定 BPM 变化规律的思路）

> \* 由于不同 BPM 会影响流速，如需统一流速需要写配置，之后将 timing 中的 BPM 全部改为基准 BPM，以统一流速。建议取消小节线，否则会和配置不匹配。（推荐使用大数例如 91、1145）如果想要小节线，那么需要手动在合适的地方设置，或者使用黑线假小节线。
>
> 或，在 7.0 后的环境下，支持 `beats=0.00` 的写法，即完全不生成小节线，可考虑。

**小节线演出**：一种简单的演出方式。将小节线数值改小，推荐从 1 开始逐渐往下尝试直到找到合适的密度。

```text
timing(1000,180.00,0.25);
timing(1200,180.00,4);
```

效果：1000–1200ms 间有**密集的小节线**。

### 变速

> 需要注意，变速在原理上基于变 BPM。以下示例均假设基础 BPM 为 180。

**慢速**

在合理时间点（例中为 1000ms）写低 BPM 语句，并在慢速段结束时写原速语句：

```text
timing(1000,90.00,4.00);
timing(5000,180.00,4.00);
```

这是从 1000ms 开始的半速慢速段，在 5000ms 结束。

> **注意**：若减速后 BPM 不是原 BPM 的 2 的幂次倍，或差别过大，推荐先写好配置（如果此处有）。否则此段的节拍线参考价值较低。
>
> 注意：若段落有正常复杂度的配置，不建议写超过 1.25x 的流速。除非特殊的超简情形，例如吐司写的线性加速器（TS 包）的尾段。

**差速**

需要用到不同的时间组。实现原理为不同时间组拥有不同的 BPM，则流速不同。推荐预先写好配置再写差速。

```text
// base group 中
timing(0,180.00,4.00);
// timinggroup 1 中
timing(0,160.00,4.00);
```

效果：被分配到时间组 1 的 note 移速都略慢。

### 变速特殊应用

**寸止**

写 0.01 或低 BPM（通常 `bpm * 0.1`）语句。

```text
timing(1000,0.00,4.00);
timing(2000,180.00,4.00);
```

（此例）观感在 1000ms 处寸止静止在触线边缘，2000ms 处恢复正常流速开始判定。

**渐减 / 渐增**

一种平滑的流速变化效果。这里以渐减为例。

使用渐变 timing 工具，填写始末时间 / BPM，分割数需要依情况而定。一般推荐 16 或其他 4 的倍数。建议让生成结果的 BPM 线贴近原 BPM 节拍线频率。

例：填写起始时间 1000，结束时间 2000，起始 BPM 180，结束 BPM 0，分割数 16。

- 获得结果：\*一大堆 timing 语句
- 效果：从 1000ms 到 2000ms，BPM 逐渐减速到静止。

> 注意：如果对效果不满意可以使用缓动。可将预设的 Linear 改成 InSine 或 OutSine，其他常见缓动也可使用。

**"抛出"式变速 / "谱面预读"式**

期望效果一般为整个谱面或单 note 从背面弹出再正常落线，就像被 "抛出" 然后落到判定线一样。

方法：

1. 将需要弹出的谱面部分放进新时间组（这里例为 tg1），使用渐变 BPM 工具。
2. 首先，提前一段时间写一个**超大 BPM**，这使得后部谱面被移到判定线背面的**视野之外**，不会影响前面的谱面。

```text
timing(999,100000,4.00);
```

3. 在工具中填写：弹出时间为负 BPM，结束时间点则为正常 BPM（或是弹出后你想要的 BPM）。若弹出时长短，分割数可选 16；偏长建议更大数字。

例：填写起始时间 1000，结束时间 1500，起始 BPM -200，结束 BPM 180，缓动 Linear。

获得效果：后段谱面从 1000ms 处从判定线背面弹出（上抛）并正向落线。

**谱面预读式**：前例基础上让负 BPM 时段变长，具体方法这里不详解。

> 若对效果不满意可调整起始 BPM 以及缓动类型。

### 重点注意：arc 类物件跨变速点会导致渲染错误

arc 类别的物件（不论是蛇还是黑线）渲染方式上不支持跨 timing（指变 BPM 的跨 timing，若不变则无事发生），若经过变速点则会出现渲染错误。如果不想导致错误发生，请尽量避免跨 timing 的写法。

常见解决方案：把蛇切碎。如果单次 timing 变动，在此处切一次。如果是链状的、连续的变动，把蛇切碎。

当然，如果你的目的就是故障效果，那么当我没说。但不保证含有故障的谱面在所有平台上可加载。**在本体壳子中，实体蛇跨 timing 会导致判定问题。**

### noinput 设置

启用时间组的 noinput 可以让其中所有 note 变为 "幽灵 note"，即不参与判定、不需要被打击（但还是可见）。

> 注意：可能由于浮点（timing 中的 BPM 与时间计算关系）与整型（绝对时间 ms）的转化中的浮点精度丢失，当写下许多 timing 语句时，后续谱面会有一定的误差。需知悉。
>
> 个人解决方法：忍住！先写上必要的变 BPM Timing 语句，写完所有配置后再做 timing 相关的表演（小节线表演无影响，随意写）。如此，必要的 timing 会起到路标作用。

## 2.1 几种特殊进阶 SV 制作思路

*此节包含 "抖动 timing"、"AQ 式简易帧动画"，涉及知识：Timing 写作、速度合成、求定积分。*

### 抖动 timing

——形如 overd.ead. \[FTR ?] 开头长条的 timing 抖动形式

笔者根据分析 overd.ead. 官谱的 timing 交替及 AI 辅助分析提出了 "速度合成" 模型，用于理解抖动 timing 的数物内核。

分析得到 overd.ead. 的长条抖动遵循以下模式：半程开始抖动，以 30ms 一条的频率交替 2 倍 BPM 与 -1 倍 BPM 语句。

发现可以认为 "长条以某个速度稳定前进，同时再叠加一个振荡速度"。分解得到此模型：

```text
瞬时速度 = 基准BPM * ( 均值倍率 ± 当前振幅倍率 )
```

在实践时由于发现长条尾部反向超越的问题（倒置），故考虑使振幅递减为 0。考虑了类似于包络的思路，设计工具：以特定缓动使振幅倍率衰减至 0，后进行功能扩展。~~（不是我写的，我只是把概念和模型丢给 deepseek 而已）~~

可以参考以上思路，或者直接用我的 HTML 工具（见文末）。

> 注意：建议振幅最大时规定为正（即均值 + 振幅而非均值 - 振幅），防止长条反向越过线保持美观。且在头尾分别设置原 BPM（出于控制长条密度与 BPM 归位的目的）。

### AQ 式简易帧动画

——形如 Astral Quantization FTR 的 "卡顿下落"

通过分析与试错得到以下写法：

先写好基础配置，在每个节奏点安排两条间隔 1ms 的 timing，数值为："原 BPM \* x"、"0.01"。前者用于切换帧 / 控制 z 距离，后者用于冻结帧。

> ※ x = 帧间距ms / 1ms \* 想要的流速倍率，基于位移分配思想（两语句负责该帧的位移，而极大值行几乎承担所有位移，即 `x * 1ms = 等效流速 * 帧间距`）。AQ 例中流速倍率 0.75 便于读谱。

时间安排上保证两语句间隔 1ms，使得切换足够快，做到硬切效果。

以基准 BPM 180 为例：

```text
timing(1000,27000,4.00);   // 设 bpm=180
timing(1001,0.01,4.00);
(1000,1);

timing(1200,27000,4.00);
timing(1201,0.01,4.00);
(1200,1);
```

效果：类似 AQ 的卡顿下落，平均流速为 0.75 倍原流速。

> 注意：调整极大值可调节下一个帧的 z 轴距离。

关于涉及长押音符持续时间 = 整帧的这种情况，简单介绍思路：

- **hold** 可以简单地在头部写 0.01、尾部写一定比例的极大值。从位移关系上，头部不动（即看起来是触线不动），尾部瞬移，回收长条长度（即看起来是切换到下一帧）。
- **arc** 需要视觉判定分离，写一个 hidegroup 的判定组，再写一个用于管理视觉效果的时间组。其中 timing 写法类似于 hold 例子，但 arc 长度需要非常短，例如 `duration = end-1, end`。此处和 hold 尾部原理相同，**但因为 arc 不能跨 timing**，头部用于判定的那一节 0 长蛇体（在 0.01 BPM 下贡献极少位移即很短）只能舍去。因此采用此办法将视觉判定分离。

### *\*拓展思路*

> ※ 笔者提及定积分的原因就是因为 timing 体系对 note 纵深的实时控制天然符合**速度–位移**物理模型。即如果你需要精细地控制位移，借助积分知识是最体系化的选择。

例如：我想做 "note 首先落线，然后从线上多次竖直上抛，最终落线被判定"，则需要考虑 "如何保证每次都落到线上，而不是落到半空中就再次被抛起"。

Arcaea 谱面中所有音符的位移遵循这个规律：在时间戳 = 0 时生成，通过中途的**速度可变的运动**来达到 "在 note 时间戳处触线消失" 的最终目的。也就是说不论任何瞬时速度，note 会想方设法在特定时间戳触线消失。这导致了 "速度正 / 负极大，位移正 / 负极大（远离线，看不见），速度极小 / 位移极小（黏在线上）" 的直观感受，类似于 "要以这个速度接近，我必须先代偿这个大小的距离"，带有一种 "预告性质"。

从这里可以抽象出：每个音符的落线过程实际上是一个**终点固定**的**倒向积分问题**。净积分 ≡ note 触线要走的路程（理论上）。

则 "如何做到每次落线而不是半空抛起"，转化为了 "如何让每次上抛以及整个连抛过程的**积分均为 0**" 的数学问题。不过很多时候估计你也只会用线性缓动（因为速度已经是个导数定义了，用简单缓动反而会自然），很多时候不需要积分计算。简简单单画个 v-s 坐标图，算算面积完事了。然而，当涉及到更复杂的问题以及需要非常精确的效果时，积分思想是很有帮助的。

## 3. SC 写作

> 注意：以下指令在 a1、a+、ac 中都不便写作，需要手敲；ace 有系统化的编辑器，通常更方便，而 aa 其次。<i>~~（其他 Arcade 变体我没玩过 ( )）~~</i>

### trackdisplay（轨道透明度）

```text
scenecontrol(时间, trackdisplay, 变化时长, 目标透明度);
```

**注意：**

- Arcade 系中时长单位为 s，ArcCreate 中为 ms。此点极重要。
- 从试验中得到：在 Ade 中 "变化过程" 的优先级最高，变化过程中如果有新的同类型语句出现将不会正常识别。（不同于你可能预期的 "后者覆盖前者"）
- 透明度范围：0%\~100% → 0\~255。alpha >= 256 时取 256 的余。负向超范围未测试。

### hidegroup（隐藏时间组）

```text
scenecontrol(时间, hidegroup, 0.00, 是否隐藏);
```

是否隐藏中 1 = 隐藏，0 = 不隐藏。第三参数无实际作用，填 0 即可。启用后时间组隐形，但还需要被打击（若未给当前时间组勾选 noinput）。

### trackhide / trackshow（隐藏轨道 / 显示轨道）

```text
scenecontrol(时间, trackhide);
scenecontrol(时间, trackshow);
```

出现相应语句时隐藏 / 显示轨道。变化时长固定 1 秒。（这是一种早期官方引入的暂时性方案，由于灵活性问题，不常用）

### enwiden（6k）相关

**enwidenlane（展开 6k 轨道）**

```text
scenecontrol(时间, enwidenlanes, 变化时长, 是否开启);
```

是否开启中 1 = 切换为开启，0 = 切换为关闭。在不开启时，大多数编辑器仍然可以将地面物件放置在 4k 外的轨道（如通过填写轨道数为 0 或 5），但此时该地面物件无法在游玩时被正常接中，它的判定区被移到最近的边缘轨道（如 1 轨或 4 轨）。

**enwidencamera（6k 相机）**

```text
scenecontrol(时间, enwidencamera, 变化时长, 是否开启);
```

是否开启中 1 = 切换为开启，0 = 切换为关闭。此效果相当于拉远 camera，同时将判定线 y 坐标升至 1.61。

> \* 需要注意的是部分制谱器可能会有兼容性问题（如 a1 在变化过程中写蛇类音符（实体蛇 / 黑线）时会持续报错）。

## 4. camera 相关

### camera（相机运动）

```text
camera(时间, x位移, y位移, z位移, xoz旋角, yoz旋角, xoy旋角, 缓动, 变化时长);
```

- 角度单位为角度制，一周 = 360°。
- 相机位移单位采用世界坐标（px），x 坐标 450 = arc 坐标 1.00，y 坐标 850 = arc 坐标 1.00。
- 缓动仅支持 `qi`、`qo` 以及 `reset`，非上述值均等同于 Linear。
- 当使用 camera 语句后，arc 会停止影响轨道倾斜，直到遇到缓动为 `reset` 的新语句。`reset` 缓动会导致相机的位置、旋角重置为默认状态。

**方向：**

| 轴 | 方向 |
| --- | --- |
| x | 左负右正 |
| y | 下负上正 |
| z | 前负后正 |
| xoz | 向右旋转正，向左旋转负（以最近边为参考） |
| yoz | 抬头正，低头负 |
| xoy | 逆时针正，顺时针负 |

## 5. 一些需要借助综合性写法实现的效果

### 投影地面物件（实现思路）

核心思想是借助 arc 类物件的投影来模拟地面物件形态。

引出两个难题：

1. 如何不让 arc 本体穿帮
2. 如何较好地隐藏蛇的高度指示器

首先，我的工具采用整体思路是 "借助超高蛇投影……"。问题 1 其实很简单，推荐拉高 y 坐标，超出视野。保守用 10.0 即可。

其次问题 2，这是重难点。

已知有两种情况能**单独地**导致蛇出现高度指示器（前提是需要保证组可见，即 hidegroup = 0）：

1. 蛇作为 "蛇头"，在一系列首尾相接的蛇序列中作为头部。即，它起始时间处**不存在**同坐标的蛇尾。
2. 蛇本身有**高度**变化。

第二点很好解决。我们集中讨论第一点。

我们总得找到一些方式将其他蛇接在原蛇头的前面以取消其高度指示器。因此衍生了两种方案：

1. **超界直角蛇方案**。利用超界直角蛇，将直角蛇的蛇头放到视野外，因此不可见。而直角蛇本身的 0ms 也导致不会影响投影显示。

   此方法由于官方更新 "为直角蛇添加了阴影" 而不再适用，会产生明显瑕疵。

2. **1ms 辅助蛇 + hidegroup 方案**。初始思路是借助辅助蛇接在蛇头前取消高度指示器再隐藏辅助蛇，这样辅助蛇就既没有投影又没有高度指示器。而原蛇头因打破以上两条件，也没有高度指示器。

   在迭代中注意到由于相互连接，辅助蛇触线时也认为投影本体触线。而由于 noinput，它们类似于 lost 状态（未接中），因此导致投影变淡。解决方案即尽量缩短辅助蛇蛇长，也回扣了超界直角蛇方案。

   该方案适配直角蛇阴影更新前后。但复杂度相应地上升。比起方案 1 需要额外的辅助蛇时间组。

### 帧动画（实现思路）

**仅 xy 变化 / 无变化**

使用同个时间组。

1. 首先按照想要的 xy 变化规律安排每一帧的物件。根据每帧需要出现的时间戳安插帧物件。
2. 接下来写 timing 语句做出帧切换效果（类似 AQ 式 sv）。

timing 内容与以上类似，但将每组间距压紧，使得帧切换达到特定帧率。（建议为帧物件所在时间组勾选 noinput，因为物件会过于密集。同时做一个隐形的时间组用于实际判定，如果需要。）

> 需要注意如果只做 "仅涉及 xy 移动的动画"，极大值填高即可，不要求特殊值。
>
> 建议以 10ms 为切换周期，100fps。从数学上对于 BPM 和 ms 值的计算结果都能保证不直接导致无理数，同时不会太过卡顿（例如 50fps 或 25fps 那样）。

**z 变化**

如果帧动画涉及纵深移动（z 轴，即前后），需要第二种帧动画做法。涉及 hidegroup，具体是将每个帧**单独分配时间组**再**各自交替 hidegroup**，以此来交替显示模拟动画原理。

以 afftools 为例，aff 工具箱中 "帧动画辅助" 工具的思路是将时间戳填极大，此外通过调整 BPM 值来控制纵深，通过调整 BPM 值以及具体的物件坐标以及 hidegroup 时间戳来控制帧的时间戳、xy 样式。不过 aff 工具箱的限制在于，支持的效果**仅限平移**（改变物件形状的那种效果暂且做不到，例如将首尾坐标 1,1 / 0,0 的蛇渐变为 0,0 / 1,1）。

关于 z 位移具体的控制逻辑太过复杂，这里就不完全展开，只给出大致脉络。

> **免责声明**：以下基于个人对于 afftools 帧动画工具的逆向，不保证 100% 准确度与置信度，一切以 afftools 实际逻辑为准。

整体思路（以 afftools 帧动画辅助为例）：

借助极大值 BPM 使得帧**显示**（在想要的时间出现，而后再用相反极大值代偿这个位移），后续的一个规定处的高 BPM 提供初始 z 位置的**位移垫量**，同时借助规定处**时间戳变化**来管理动画中的 z 运动。

实现逻辑：

1. 帧物件时间戳很大（999999），在帧应当显示时给 1ms 极大 BPM 来拉近到眼前，在这之后再用 1ms 负极大补偿位移。
2. 借助规定时间点的 1ms 高 BPM 来规定初始 z 位置，在这之后 BPM 变为基准 BPM，保证帧物件外观正常（不被拉伸压缩），也为管理动画 z 运动做准备。
3. 通过调整规定时间点的位置来影响它与帧物件时间戳的时间距离，从而影响用于管理 z 运动的那个 z 位移量。在帧序列中，这个时间（即 "物件时间戳 - 规定时间点"）会不断改变，做出 z 运动效果。

笔者建议：理解即可，不要用拳头挑战古神。帧动画体量巨大，徒手操作**不现实**，一般借助自动化脚本来规划（例如 afftools）。
