##### **1、基础物件语句格式**



###### **tap**：(时间,轨道);



 	| 例：(1000,1);	(1000ms处左1轨地键) |





###### **hold**：hold(起始时间,结束时间,轨道);



 	| 例：hold(1000,2000,4);	（1000-2000ms间右一轨长条）|



###### **arc**：arc(起始时间,结束时间,起始x坐标, 结束x坐标,缓动类型,起始y坐标,结束y坐标,颜色,sfx路径,类型);

**参数部分详解：**



缓动类型：
s：直线（线性即Linear，像“/”）
b：贝塞尔（正弦出入即InOutSine，像"∫"）
si：正弦渐出（正弦渐出即Outsine看起来像"J"）
so：正弦渐入（正弦渐入即InSine看起来像"ſ"）
sisi/siso/sosi/soso：前一半为x轴缓动，后一半为y轴缓动
b型蛇则是x轴和y轴都是InOutSine。



颜色：
0=蓝
1=红
2=绿

3=灰



sfx路径：没有时填none，有时填\[文件名]\_wav，例如glass\_wav，此时“glass.wav”应与base.ogg/base.jpg/.aff同级

填写路径会导致它的天键变成sfx Arctap外观（类似4.0许多曲目中的那样）并在击打成功时播放sfx



类型：

false=蛇（音弧/arc）

true=黑线（音轨/trace）

designant=红色黑线（类似Lament Rain与Designant.异象中的那种），并同步染色它的天键



 	| 例：arc(1000,2000,1.00,0.00,sisi,1.00,0.00,1,none,false);    （右起下拉红蛇）|



###### **arctap**：（arc语句）\[arctap(时间),arctap(时间)......];

**注意**，天键必须基于黑线创建。一些平台支持实体蛇上加天键，一些则不支持。保守起见建议统一使用黑线上天键。



 	| 例：arc(1000,2000,1.00,0.00,si,1.00,0.00,1,none,true)\[arctap(1000),arctap(1500),arctap(2000)];（前例蛇的黑线版本上有三天键）	|
 	| 例：arc(1000,1001,0.50,1.00,s,0.50,1.00,1,none,true)\[arctap(1000)];						（"SingleArctap"的实际实现方式）		|



###### **特殊天键**：形如HIVEMIND INTERLINK中大小键的天键

在v5.5.6或更高版本的本体/壳子/兼容的制谱器中，颜色为3的0ms蛇会被读作类似于被横向拉伸的天键，判定范围随之改变拉伸，判定方式类似天键。很可惜a1只截至4.0.0，23年停更。



 	| 例：arc(1000,1000,1.00,0.00,si,0.50,0.50,3,none,true);	（宽两轨的半高大小键）|

##### **2、时间组相关应用**

TimingGroup是实现变速，变bpm，差速等基本变化/演出的基础。首先应明确知识。



**基础bpm**：一般设为歌曲最基础的bpm（或倍率），谱面流速为“设定流速 \* (timing语句中的bpm / 基准bpm)”，两bpm相等时设定流速＝实际流速。
**设置timing**：一般设为歌曲bpm，与基准bpm需保持一致。



###### **timing语句**：timing(时间,bpm,每小节节拍数);



一般地，每个时间组**必须填写**最基本一条timing：timing(0,歌曲bpm,4.00);	这是让谱面能被正常读取，且bpm正确（节拍线正确）的关键。



###### **SV实现思路：**

变bpm：首先需明确bpm如何变化，然后写出对应语句即可。
例：歌曲起始bpm是180，在1000ms处变为190，1200ms处变为200。我们需要根据歌曲bpm变化而改变节拍线密度。



这样写：
timing(0,180.00,4.00);
timing(1000,190.00,4.00);
timing(1200,200.00,4.00);
即可。



一般情况下明确变化规律时优先思考经过几拍（时值）变成什么bpm，而不是以绝对时间确定变化点。（当然写语句的时候还是要考虑绝对时间，这里是介绍更高效的确定bpm变化规律的思路）

\*由于不同bpm会影响流速，如需统一流速需要写配置之后将timing中的bpm全部改为基准bpm，以统一流速。建议取消小节线，否则会和配置不匹配。（推荐使用大数例如91，1145），如果想要小节线，那么需要手动在合适的地方设置。或者使用黑线假小节线。

或，在7.0后的环境下，支持beats=0.00的写法，即完全不生成小节线，可考虑。



**小节线演出**：一种简单的演出方式。

将小节线数值改小。推荐从1开始逐渐往下尝试直到找到合适的密度。



例：
timing(1000,180.00,0.25);
timing(1200,180.00,4);



效果：1000-1200ms间有**密集的小节线**



###### **变速**：需要注意，变速在原理上基于变bpm。以下示例均假设基础bpm为180



**慢速：**

在合理时间点（例中为1000ms）写低bpm语句。并在慢速段结束时写原速语句



例：
timing(1000,90.00,4.00);
timing(5000,180.00,4.00);
这是从1000ms开始的半速慢速段，在5000ms结束



**注意**：若减速后bpm不是原bpm的2的幂次倍，或差别过大，推荐先写好配置（如果此处有）。否则此段的节拍线参考价值较低

注意：若段落有正常复杂度的配置，不建议写超过1.25x的流速。除非特殊的超简情形，例如吐司写的线性加速器（TS包）的尾段。



**差速**：需要用到不同的时间组。实现原理为不同时间组拥有不同的bpm，则流速不同。

推荐预先写好配置再写差速。



例：
base group中：timing(0,180.00,4.00);
timinggroup 1中：timing(0,160.00,4.00);
效果：被分配到时间组1的note移速都略慢。



###### **变速特殊应用：**



**寸止：**
写0.01或低bpm（通常bpm\*0.1）语句。



例：
timing(1000,0.00,4.00);
timing(2000,180.00,4.00);

（此例）观感在1000ms处寸止静止在触线边缘，2000ms处恢复正常流速开始判定。



**注意**：0bpm或超低bpm需要有相关提示（如黑线差速提示判定）。非简单配置下不能随意寸止，否则太过不友善（但只是约定俗成，某些条件下可以推翻，例你写高难或创新性质谱）



**渐减/渐增**：一种平滑的流速变化效果。这里以渐减为例。



使用渐变timing工具，填写始末时间/bpm，分割数需要依情况而定。一般推荐16或其他4的倍数。建议让生成结果的bpm线贴近原bpm节拍线频率。



例：填写起始时间1000，结束时间2000，起始bpm180，结束bpm0，分割数16

获得结果：\*一大堆timing语句
效果：从1000ms到2000ms，bpm逐渐减速到静止。



注意：如果对效果不满意可以使用缓动。可将预设的Linear改成InSine或OutSine，其他常见缓动也可使用。



**"抛出"式变速/"谱面预读"式：**

期望效果一般为整个谱面或单note从背面弹出再正常落线，就像被"抛出"然后落到判定线一样。



**方法：**

将需要弹出的谱面部分放进新时间组（这里例为tg1），使用渐变bpm工具。首先，提前一段时间写一个**超大bpm**，这使得后部谱面被移到判定线背面的**视野之外**，不会影响前面的谱面。



例：timing(999,100000,4.00);



在工具中填写，在弹出时间为负bpm，结束时间点则为正常bpm（或是弹出后你想要的bpm）。若弹出时长短分割数可选16，偏长建议更大数字。
例：填写起始时间1000，结束时间1500，起始bpm-200，结束bpm180，缓动Linear。
获得效果：后段谱面从1000ms处从判定线背面弹出（上抛）并正向落线。

谱面预读式：前例基础上让负bpm时段变长，具体方法这里不详解。



若对效果不满意可调整起始bpm以及缓动类型。



###### **重点注意！！！：arc类物件跨变速点会导致渲染错误**



arc类别的物件（不论是蛇还是黑线）渲染方式上不支持跨timing（指变bpm的跨timing，若不变则无事发生），若经过变速点则会出现渲染错误。如果不想导致错误发生，请尽量避免跨timing的写法。

常见解决方案：把蛇切碎。如果单次timing变动，在此处切一次。如果是链状的，连续的变动，把蛇切碎。

当然，如果你的目的就是故障效果，那么当我没说。但不保证含有故障的谱面在所有平台上可加载。**在本体壳子中，实体蛇跨timing会导致判定问题。**



###### **“noinput”设置：**



启用时间组的noinput可以让其中所有note变为“幽灵note”，即不参与判定，不需要被打击（但还是可见）。



注意：

可能由于浮点（timing中的bpm与时间计算关系）与整形（绝对时间(ms)）的转化中的浮点精度丢失，当写下许多timing语句时，后续谱面会有一定的误差。需知悉。

个人解决方法：忍住！先写上必要的变bpm Timing语句，写完所有配置后再做timing相关的表演（小节线表演无影响，随意写）如此，必要的timing会起到路标作用

###### **抖动timing**——形如overdead. \[FTR ?]开头长条的timing抖动形式

笔者根据分析overdead.官谱的timing交替及ai辅助分析提出了“速度合成”模型，用于理解抖动timing的数物内核。

分析得到overdead.的长条抖动遵循以下模式：半程开始抖动，以30ms一条的频率交替2倍bpm与-1倍bpm语句。

发现可以认为“长条以某个速度稳定前进，同时再叠加一个振荡速度”。分解得到此模型：



 	| 瞬时速度 = 基准BPM \* ( 均值倍率 ± 当前振幅倍率 ) |

注意：建议振幅最大时规定为正（即均值+振幅而非均值-振幅），防止长条反向越过线保持美观。且在头尾分别设置原bpm（出于控制长条密度与bpm归位的目的）



###### **AQ式简易帧动画**——型如Astral Quallization FTR的“卡顿下落”

通过分析与试错得到以下写法：



先写好基础配置，在每个节奏点安排两条间隔1ms的timing，数值为：“原bpm\*x”、“0.01”。前者用于切换帧/控制z距离，后者用于冻结帧。
※x＝帧间距ms / 1ms \* 想要的流速倍率，基于位移分配思想（两语句负责该帧的位移，而极大值行几乎承担所有位移，即x\*1ms＝等效流速\*帧间距）。AQ例中流速倍率0.75便于读谱

时间安排上保证两语句间隔1ms，使得切换足够快，做到硬切效果。

以基准bpm180为例，例如：



timing(1000,27000,4.00);	//设bpm=180

timing(1001,0.01,4.00);

(1000,1);

timing(1200,27000,4.00);

timing(1201,0.01,4.00);

(1200,1);

效果：类似AQ的卡顿下落，平均流速为0.75倍原流速。

注意：调整极大值可调节下一个帧的z轴距离。



关于涉及长押音符持续时间=整帧的这种情况简单介绍思路：
hold可以简单地在头部尾部写0.01，尾部写一定比例的极大值。从位移关系上，头部不动（即看起来是触线不动），尾部瞬移，回收长条长度（即看起来是切换到下一帧）
arc需要视觉判定分离，写一个hidegroup的判定组，再写一个用于管理视觉效果的时间组。其中timing写法类似于hold例子，但arc长度需要非常短，例如duration = end-1, end。此处和hold尾部原理相同，**但因为arc不能跨timing**，头部用于判定的那一节0长蛇体（在0.01bpm下，贡献极少位移即很短）只能舍去。因此采用此办法将视觉判定分离。





###### ***※ 拓展思路：***

笔者提及定积分的原因就是因为timing体系对note纵深的实时控制天然符合**速度-位移**物理模型。

即如果你需要精细地控制位移，借助积分知识是最体系化的选择。



例如：我想做“note首先落线，然后从线上多次竖直上抛，最终落线被判定”

则需要考虑“如何保证每次都落到线上，而不是落到半空中就再次被抛起”。



arcaea谱面中所有音符的位移遵循这个规律：在时间戳=0时生成，通过中途的 **速度可变的运动** 来达到“在note时间戳处触线消失”的最终目的。也就是说不论任何瞬时速度，note会想方设法在特定时间戳触线消失。这导致了“速度正/负极大，位移正/负极大（远离线，看不见），速度极小/位移极小（黏在线上）”的直观感受，类似于“要以这个速度接近，我必须先代偿这个大小的距离”，带有一种“预告性质”。



从这里可以抽象出：每个音符的落线过程实际上是一个**终点固定**的**倒向积分问题**。净积分≡note触线要走的路程(理论上)。

则“如何做到每次落线而不是半空抛起”，转化为了“如何让每次上抛以及整个连抛过程的**积分均为0**”的数学问题。不过很多时候估计你也只会用线性缓动（因为速度已经是个导数定义了，用简单缓动反而会自然），很多时候不需要积分计算。简简单单画个v-s坐标图，算算面积完事了。然而，当涉及到更复杂的问题时以及需要非常精确的效果时，积分思想是很有帮助的。

##### **5、一些需要借助综合性写法实现的效果**



###### **投影地面物件**（实现思路）

核心思想是借助arc类物件的投影来模拟地面物件形态。

引出两个难题：

1. 如何不让arc本体穿帮
2. 如何较好地隐藏蛇的高度指示器



首先，我的工具采用整体思路是“借助超高蛇投影......”问题1其实很简单，推荐拉高y坐标，超出视野。保守用10.0即可

其次问题2，这是重难点。

已知有两种情况能 **单独地** 导致蛇出现高度指示器（前提是需要保证组可见，即hidegroup=0）

① 蛇作为“蛇头”，在一系列首位相接的蛇序列中作为头部。即，它起始时间处**不存在**同坐标的蛇尾。

② 蛇本身有**高度**变化。

第二点很好解决。我们集中讨论第一点。



我们总得找到一些方式将其他蛇接在原蛇头的前面以取消其高度指示器。因此衍生了两种方案：

1，**超界直角蛇方案**。利用超界直角蛇，将直角蛇的蛇头放到视野外，因此不可见。而直角蛇本身的0ms也导致不会影响投影显示。

此方法由于官方更新“为直角蛇添加了阴影”而不再适用，会产生明显瑕疵。

2，**1ms辅助蛇+hidegroup方案**。初始思路是借助辅助蛇接在蛇头前取消高度指示器再隐藏辅助蛇，这样辅助蛇就既没有投影又没有高度指示器。而原蛇头因打破以上两条件，也没有高度指示器。

在迭代中注意到由于相互连接，辅助蛇触线时也认为投影本体触线。而由于noinput，它们类似于lost状态（未接中），因此导致投影变淡，解决方案即尽量缩短辅助蛇蛇长，也回扣了超界直角蛇方案。

该方案适配直角蛇阴影更新前后。但复杂度相应地上升。比起方案1需要额外的辅助蛇时间组。



###### **帧动画**（实现思路）

**仅xy变化/无变化**：
使用同个时间组。
首先按照想要的xy变化规律安排每一帧的物件。根据每帧需要出现的时间戳安插帧物件。接下来写timing语句做出帧切换效果（类似AQ式sv）

timing内容与以上类似，但将每组间距压紧，使得帧切换达到特定帧率。（建议为帧物件所在时间组勾选noinput因为物件会过于密集。同时做一个隐形的时间组用于实际判定，如果需要。）

需要注意如果只做“仅涉及xy移动的动画”，极大值填高即可，不要求特殊值。

建议以10ms为切换周期，100fps。从数学上对于bpm和ms值的计算结果都能保证不直接导致无理数，同时不会太过卡顿（例如50fps或25fps那样）



**z变化**：

如果帧动画涉及纵深移动（z轴，即前后），需要第二种帧动画做法。涉及hidegroup，具体是将每个帧**单独分配时间组**再**各自交替hidegroup**，以此来交替显示模拟动画原理。
以afftools为例，aff工具箱中“帧动画辅助”工具的思路是将时间戳填极大，此外通过调整bpm值来控制纵深，通过调整bpm值以及具体的物件坐标以及hidegroup时间戳来控制帧的时间戳、xy样式。不过aff工具箱的限制在于，支持的效果**仅限平移**（改变物件形状的那种效果暂且做不到，例如将首尾坐标1,1/0,0的蛇渐变为0,0/1,1）

关于z位移具体的控制逻辑太过复杂，这里就不完全展开，只给出大致脉络。



**免责声明**：以下基于个人对于afftools帧动画工具的逆向，不保证100%准确度与置信度，一切以afftools实际逻辑为准。



整体逻辑（以afftools帧动画辅助为例）：

借助极大值bpm使得帧**显示**（在想要的时间出现，而后再用相反极大值代偿这个位移），后续的一个规定处的高bpm提供初始z位置的**位移垫量**，同时借助规定处**时间戳变化**来管理动画中的z运动。



**几个细节**：

1. 帧物件时间戳很大（999999），在帧应当显示时给1ms极大bpm来拉近到眼前，在这之后再用1ms负极大补偿位移。
2. 借助规定时间点的1ms高bpm来规定初始z位置，在这之后bpm变为基准bpm，保证帧物件外观正常（不被拉伸压缩），也为管理动画z运动做准备。
3. 通过调整规定时间点的位置来影响它与帧物件时间戳的时间距离，从而影响用于管理z运动的那个z位移量。在帧序列中，这个时间（即“物件时间戳 - 规定时间点”）会不断改变，做出z运动效果。



笔者建议：理解即可，不要用拳头挑战古神。帧动画体量巨大，徒手操作**不现实**，一般借助自动化脚本来规划（例如afftools）
